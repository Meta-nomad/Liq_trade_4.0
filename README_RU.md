# Liquidation Lab 0.4.0 — эксперимент, 14 сентября 2026

Готовый код бумажного эксперимента, НЕ проверенная прибыльная стратегия.
Реальных заявок и авторизованного биржевого клиента нет.

## Изменения
- Четыре независимых счёта по 1000 USDT: 20x, 50x, 100x, 200x. Их прибыль нельзя складывать как результат одного счёта.
- Только LIQUIDATION_EXHAUSTION; сигналы трендового модуля не исполняются в HIGH_LEVERAGE_LAB.
- Цель выхода: чистый PnL / НАЧАЛЬНАЯ маржа >= 250%. Это не ROI всего счёта и может отличаться от процента в интерфейсе биржи.
- Плановый риск одной сделки максимум 0.25% equity (около 2.50 USDT на счёте 1000). Стоп по волатильности 0.6–2.5%; его не сужаем ради плеча. Плановый риск не гарантирует максимальный убыток при гэпе.
- Одна позиция на независимый счёт. Нет усреднения, мартингейла или авто-добавления маржи.
- Остаются временной выход, перенос стопа после 1R и защитные остановки. Сделка может закрыться раньше +250%.
- Вход требует метаданных MEXC и допустимого maxLeverage. Приближённая дистанция ликвидации = 1/L - MMR - 2*taker_fee; стоп должен быть ещё минимум на 0.2% цены ближе входа. Многие 100x/200x сигналы будут отклонены.
- 30 кандидатов вместо 10: BTC ETH SOL XRP BNB DOGE ADA AVAX LINK LTC DOT ATOM NEAR UNI AAVE TRX XLM ETC BCH FIL ICP APT ARB OP SUI INJ RUNE SEI TON HBAR.
- Это список кандидатов, НЕ удостоверение надёжности проектов. Новые символы вне списка не принимаются.
- Перед стартом Bybit-проверка: активный USDT LinearPerpetual, возраст >=180 дней, нет prelisting/объявленного delisting, оборот >=10 млн USDT/сутки, спред <=10 б.п. Пагинация учитывается. МEXC проверяется отдельно перед входом; нет данных — нет входа.
- Список перепроверяется ежечасно; не прошедшие монеты блокируются для новых входов. При сбое обновления новые входы блокируются, открытые позиции продолжают сопровождаться.
- Ликвидации: >=5 событий и >=max(50000 USDT, 0.5% оборота Bybit за 5 минут), затем прежние проверки перекоса/потока/стакана. Это начальные гипотезы порогов, не оптимизированные величины.
- Проверка разворота каждые 15 секунд вместо 60, окно ликвидаций осталось 5 минут. Глобальные режимы RANGE/STRESS сохранены.
- Цена исполнения и глубина теперь берутся из MEXC. Проскальзывание не обрезается сверху; слишком дорогой вход или недостаточная глубина отклоняются. Невозможный выход даёт PAPER EXIT UNRESOLVED, позиция остаётся открытой — такой период нельзя считать достоверным тестом исполнения.
- В SQLite и /api/trades добавлены leverage, initial_margin, net_roi_pct. PAPER ACCOUNT показывает каждый счёт отдельно. Краткий PAPER STATUS equity — только первый счёт (20x), не общий капитал.

## Важно про достоверность
Это ещё НЕ точный симулятор биржевой ликвидации: используется приближённая формула и котировка, а не полноценный MEXC mark-price/risk-tier/ADL механизм. MMR загружается при bootstrap; её изменение и ступени риска полностью не воспроизводятся. На высоких плечах это существенная погрешность.
Funding применяется существующим движком; его предположение о следующем 8-часовом интервале требует отдельной проверки для каждого контракта. Биржевые ограничения количества и шага цены не полностью воспроизводятся.
При недоступном стакане выход может остаться неисполненным; наблюдаемый риск не ограничен плановым стопом. Возраст/оборот/спред НЕ проверяют мошенничество или токеномику.
Исторические логи шести сделок не содержат пути цен и ликвидаций: пересчитать достоверный результат на 50–200x из них нельзя. Старые 83.3% побед к новой версии не относятся.

## Запуск через GitHub / Railway
1. Загрузить содержимое этой папки в отдельный репозиторий/сервис для эксперимента; Dockerfile расположен в корне.
2. В Railway установить HIGH_LEVERAGE_LAB=true, PAPER_BALANCE=1000, DB_PATH=/data/paper_v040.db. Подключить постоянный volume к /data.
3. УДАЛИТЬ старую переменную SYMBOLS, иначе сохранится старый список 10 монет. Полный пример переменных — .env.example. Настройки среды Railway имеют приоритет; файл .env.example сам не применяется.
4. Задать свой DASHBOARD_TOKEN; после деплоя проверить заголовок страницы v0.4.0 и RELEASE v0.4.0-20260914 в логах.
5. Должны появиться 4 PAPER ACCOUNT с LIQ_ROI250_*X_V040. Старые состояния COMPOSITE_FLOW не восстанавливаются в эти счета. Результаты v0.4.0 после перезапуска сохраняются при наличии volume.
6. Смотреть UNIVERSE (отбор), PAPER REJECT (отказ), PAPER POSITION (маржа/плечо), PAPER ROI (чистая доходность), PAPER EXIT UNRESOLVED (недостоверное исполнение).
7. Первый запуск требует доступности публичных REST Bybit для отбора; при ошибке запуска не будет. Авторизованные ключи бирж не нужны.

## Отдельная математическая модель
python scenario_model/model.py --out scenario_results.json
Сравнивает 20/50/100/200x при стопе -50% маржи, цели +250%, риске 0.5% счёта. Эти параметры отличаются от основного бота с волатильностным стопом и риском 0.25%.
Допущения: комиссия 0.08% и проскальзывание 0.01% за сторону, funding=0 базово; MMR=0.4% условно. Это сценарии, НЕ актуальная тарифная рекомендация и НЕ исторический бэктест. Stress: проскальзывание 0.1% за сторону, funding 0.01% номинала.
Replay одной выбранной сделки: python scenario_model/model.py --ticks market.csv --entry 100 --leverage 50 --side LONG. CSV ts,mark,bid,ask,funding_fraction: Unix seconds по возрастанию, первая строка соответствует входу; funding_fraction — отдельный платёж/исходный номинал (плюс = расход). Пропуски тиков могут скрыть стоп/ликвидацию. Сам replay не создаёт сигналы. Ликвидации отмечаются APPROX_LIQUIDATION без выдуманного PnL.
